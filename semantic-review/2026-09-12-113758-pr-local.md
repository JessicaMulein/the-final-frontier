# Guarded Nova voice audition and blind listener packaging

The remaining blockers sit in failure paths rather than the normal audition flow. A process can lose durable knowledge of a potentially charged Nova call, package recovery accepts event evidence that is not bound to the transcript or audio, and malformed private key data can escape the blind-package boundary. Session cancellation and concurrent packaging retain lifecycle and integrity gaps, while the offline suite does not exercise these boundaries. **Watch for:** **High / confirmed** rebilling after an uncertain paid call; **High / confirmed** unverified event-to-audio provenance; **High / confirmed** blind-key-controlled public paths; **Medium / likely** timeout overrun during SDK teardown.

**Verdict**: NEEDS_CHANGES

## High-level view

**High / confirmed:** A call remains `pending` until Nova has returned, all four artifacts have been written, and the plan is saved. Any termination after the request becomes billable but before the first durable artifact leaves no state that distinguishes an uncertain charge from a never-attempted call, so the next render run invokes it again.

**High / confirmed:** Stored Nova events are checked only as nonempty JSON objects. Recovery and packaging therefore cannot prove that the accepted transcript and WAV came from the recorded `contentId` streams or even that the log contains a FINAL transcript, audio, and successful completion.

**Medium / likely:** The session deadline surrounds the full invocation, but cancellation waits on an unbounded receiver join and SDK context teardown. A transport that does not cancel promptly can keep the command alive beyond the configured deadline and delay connection cleanup.

**High / confirmed:** Blind-key values are constrained to configured voices, but its labels are accepted verbatim and become public directory and scorecard labels. **Medium / confirmed:** Key creation and package publication are separate, unlocked decisions, allowing concurrent packagers to leave a key that identifies a different label-to-audio mapping from the package that won publication.

**Medium / confirmed:** The source-routed tests cover only transcript tampering and do not simulate these lifecycle and package-integrity failures. **Low / confirmed:** The README is installed as distribution metadata and embeds a developer-specific absolute path.

<summary>Details</summary>

### Paid-call state is persisted after the uncertainty window

**High — confirmed.** `render_plan` treats a call with no artifacts as safely pending, invokes Nova, writes audio/transcript/events/verification, and only then records a non-pending status in `plan.json` (`.audiobook/src/frontier_audiobook/audition.py:317-379`). A timeout, SDK error, power loss, or process kill after Bedrock accepts the request but before `audio_path` is replaced leaves both `status == "pending"` and an empty artifact set, so the next confirmed render automatically makes the same call again. This exceeds the documented recoverable case of a crash after all artifacts are present (`.audiobook/README.md:147`).

```text
plan: pending
    -> Bedrock request may become chargeable
    -> response returns
    -> four artifacts are replaced
    -> plan status is persisted
```

Persist an `invoking`/`charge-uncertain` state atomically before entering `render_text`. A restart should recover complete artifacts locally, but an attempt with missing or partial evidence should require an explicit reconciliation/reset operation rather than being selected as pending work.

### Event files do not prove which transcript and audio were rendered

**High — confirmed.** Package-time validation only requires at least one event line and that every line decodes to a JSON object (`.audiobook/src/frontier_audiobook/audition.py:282-289`). The package test renders every call with an event tuple containing only `completionEnd`, after which packaging succeeds (`.audiobook/tests/test_audition.py:64-90`). In pending-artifact recovery, hashes are initially absent, so any nonempty, correctly formatted WAV can be promoted to `fidelity_pass` alongside a source-matching transcript and this syntactically valid but unrelated event log.

Refactor the output-event parser into a pure replay validator used both live and from JSONL. Packaging and recovery should enforce official output `contentId` relationships, `ASSISTANT`/`FINAL` transcript context, audio context, and `END_TURN`, then raw-concatenate chunks and compare the reconstructed transcript and LPCM bytes with the stored transcript and WAV.

### SDK teardown can outlive the session deadline

**Medium — likely.** The outer `asyncio.wait_for` covers `_invoke_session` (`.audiobook/src/frontier_audiobook/nova.py:300-303`), but timeout cancellation then waits for an unbounded receiver gather and both stream/client context exits (`.audiobook/src/frontier_audiobook/nova.py:156-167,248-254`). Only `input_stream.close()` has its own five-second bound. If the SDK iterator or an `__aexit__` is wedged, the nominal full-session timeout can hang and cleanup has no terminal deadline.

Put explicit bounds around receiver cancellation and each SDK teardown operation, preserve the original timeout error if cleanup also fails, and exercise the path with a fake receiver and context manager that delay cancellation.

### Private blind-key labels control public paths

**High — confirmed.** An existing blind key is accepted when the set of mapping values equals the configured voices; keys are not constrained (`.audiobook/src/frontier_audiobook/audition.py:414-433`). Each key is lowercased directly into a destination path and public scorecard label (`.audiobook/src/frontier_audiobook/audition.py:459-487`). A voice-name label exposes identity in the listener package, while a label containing separators and `..` components can escape staging and make `shutil.copyfile` overwrite another workspace path with WAV bytes.

Require exact labels `A` through the expected final letter, exact one-to-one string values, the matching audition ID/schema, and no extra key fields. Resolve every destination against the staging root and reject it unless it remains inside that root.

### Concurrent package runs can separate the key from the winning clips

**Medium — confirmed.** Key creation is an existence check followed by a replace-style atomic write, while package publication happens later through a different `os.replace` (`.audiobook/src/frontier_audiobook/audition.py:414-431,442-510`). Two processes can both observe no key, generate different mappings, overwrite each other’s key, and build packages from their in-memory mappings; whichever directory rename succeeds need not correspond to the mapping left on disk. Existing-package recovery sees the same A–D paths under either permutation and cannot detect the mismatch.

Serialize packaging per audition or create the key with exclusive-create semantics and make losing processes re-read the winner before copying. Recovery should privately bind each published label to the copied WAV hash so a key/package mismatch fails closed without exposing voice IDs in the listener tree.

### Offline tests bypass the installed distribution and safety failures

**Medium — confirmed.** The suite contains four source-tree tests, and pytest is configured with `pythonpath = ["src"]` (`.audiobook/pyproject.toml:28-30`; `.audiobook/tests/test_audition.py:39-159`). It does not cover uncertain-call restart behavior, bounded cleanup, semantic event replay, malformed blind keys, concurrent publication, or verification/event/WAV tampering. It cannot catch a broken wheel or console entry point because imports never come from the installed distribution.

Add network-denied failure-path coverage for the safety boundaries and a separate build/install smoke test that invokes the packaged console script outside the source tree. The event fixture should represent a complete official output stream so package success cannot normalize an incomplete log as valid evidence.

### Installed metadata contains a workstation identity path

**Low — confirmed.** The project uses `README.md` as long-description metadata (`.audiobook/pyproject.toml:9`), and the README includes `/Users/jessica/Documents/frontier-book/.audiobook` in the install command (`.audiobook/README.md:79`). That user path is present in installed distribution metadata and is not portable to another checkout.

Replace it with a repository-relative `cd .audiobook` or placeholder checkout path, and assert that built metadata contains no home-directory path.
